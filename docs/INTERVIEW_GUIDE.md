# 面试讲解材料

## 30 秒版本

这是一个证据驱动的开源项目调研 Agent。它把研究目标拆成项目和字段，通过可注入工具收集结构化证据，默认使用可复现 fixture，也能安全读取 GitHub 公共仓库元数据；Reviewer 检查字段覆盖率和引用完整性，遇到瞬时工具失败时有限重规划，最后输出 COMPLETED、PARTIAL 或 BLOCKED 以及完整轨迹。

## 2 分钟版本

1. **任务契约**：ResearchTask 固定目标项目、必需字段、工具预算和重规划预算。
2. **工具调用**：先校验任务中显式指定的目标，再逐项目读取语言、许可证、能力和限制；同一接口可注入本地 fixture 或 GitHub 公共只读适配器。当前版本不声称支持开放式关键词搜索。
3. **证据工程**：每条事实生成稳定 Evidence ID 和 sourceUrl，报告只能引用已存在的证据。
4. **Reviewer**：完成前检查字段覆盖和引用 ID 完整性；它不把“ID 存在”夸大为外部来源真实性证明。
5. **Recovery**：工具故障触发 REPLAN，但次数有上限；不能完成时保留已有证据并安全降级。
6. **验证**：离线演示先校验显式目标，再根据可执行目标生成计划；瞬时故障会产生 REPLAN。自动测试同时覆盖 GitHub 成功读取、404、限流、超时、取消、响应过大、身份不匹配和跨域输入，网络部分全部使用 mock。

## 高频追问

### 它和普通 RAG 有什么区别？

RAG 主要解决检索与生成；这里还包含显式任务契约、工具预算、证据覆盖审查、失败重规划和终态语义，更接近完整 Agent 控制循环。

### 如何避免幻觉？

报告中的事实必须绑定 Evidence ID，Reviewer 会拒绝不存在的引用，并检查每个必需字段是否有来源。当前保证引用链完整；未来还需增加内容哈希、来源冲突和可信度评分，才能进一步验证事实质量。

### 为什么默认不用真实 GitHub API？

因为 CI 和面试演示首先需要可重复，所以默认仍使用 deterministic fixture。v0.3 增加了显式选择的 GitHub 公共只读适配器，用来证明真实工具接入；它无需 Token，但公共限流和网络变化会影响结果，因此不替代离线基准。

### GitHub Adapter 如何避免变成 SSRF 或写操作入口？

它不暴露通用 fetch 或任意 URL 参数。输入只接受 `owner/repo` 或两个 GitHub 官方域名的规范 HTTPS 仓库地址，随后由代码固定构造 REST URL；HTTP 方法始终为 GET，禁止重定向，不发送认证头，并设置超时、取消和响应大小上限。响应中的仓库身份还必须与目标一致。

### 为什么不用 Token？

这个版本只演示公共仓库元数据读取。无 Token 可以降低凭据泄露和误操作风险，也让使用边界更容易审查；代价是限流更严格，不适合生产采集。

### 项目的限制是什么？

当前 Planner 是确定性策略；GitHub 模式只读取仓库元数据，不读取源码或 README，也没有缓存、指数退避和生产 SLA。仓库证明的是工具注入、安全边界、恢复和证据审查链路可运行，不证明开放互联网研究质量。

## 演示顺序

1. 运行 `npm run demo`；
2. 指出注入的一次 transient failure；
3. 展示 REPLAN 轨迹；
4. 展示 8 条证据和引用；
5. 修改预算说明 PARTIAL 的安全降级。

可选加演示：执行 `npm run demo -- --mode=github --projects=octocat/Hello-World`，说明真实模式必须显式选择、无需 Token，并展示 REST 来源 URL；正式演示前应考虑公共 API 限流，核心流程仍以 fixture 为准。
