# 面试讲解材料

## 30 秒版本

这是一个证据驱动的开源项目调研 Agent。它把研究目标拆成项目和字段，调用只读工具收集结构化证据，由 Reviewer 检查覆盖率和引用真实性；遇到瞬时工具失败时做有界重规划，最后输出 COMPLETED、PARTIAL 或 BLOCKED 以及完整轨迹。

## 2 分钟版本

1. **任务契约**：ResearchTask 固定目标项目、必需字段、工具预算和重规划预算。
2. **工具调用**：Planner 先搜索候选，再逐项目读取语言、许可证、能力和限制。
3. **证据工程**：每条事实生成稳定 Evidence ID 和 sourceUrl，报告只能引用已存在的证据。
4. **Reviewer**：完成前同时检查字段覆盖和引用合法性，从机制上拒绝伪造引用。
5. **Recovery**：工具故障触发 REPLAN，但次数有上限；不能完成时保留已有证据并安全降级。
6. **验证**：离线演示注入一次瞬时故障，轨迹会出现 PLAN→ACT→REPLAN→ACT→VERIFY→FINALIZE；4 项测试覆盖成功、恢复、伪造引用和预算不足。

## 高频追问

### 它和普通 RAG 有什么区别？

RAG 主要解决检索与生成；这里还包含显式任务契约、工具预算、证据覆盖审查、失败重规划和终态语义，更接近完整 Agent 控制循环。

### 如何避免幻觉？

报告中的事实必须绑定 Evidence ID，Reviewer 会拒绝不存在的引用，并检查每个必需字段是否有来源。未来还可以增加来源冲突和可信度评分。

### 为什么当前不用真实 GitHub API？

公开 v0.1 先用 deterministic fixture 验证 Agent 控制与审查机制，避免网络变化、限流和凭据影响复现。只读 GitHub Adapter 是下一阶段扩展。

### 项目的限制是什么？

当前 Planner 是确定性策略，没有证明真实 LLM 或开放互联网任务上的质量；仓库只证明接口、恢复和证据审查链路可运行。

## 演示顺序

1. 运行 `npm run demo`；
2. 指出注入的一次 transient failure；
3. 展示 REPLAN 轨迹；
4. 展示 8 条证据和引用；
5. 修改预算说明 PARTIAL 的安全降级。
